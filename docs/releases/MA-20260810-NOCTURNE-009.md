# Nocturne Cast Access Production Assessment

## Evaluation context

This assessment covers production promotion of cast self-service attendance,
cast-account lifecycle management and administrator-wide schedule control. The
target environment is the current shop Alpha on the public self-hosted domain.
Booking, payment, customer identity, payroll and employee-document handling
remain outside scope.

Target stage: shop Alpha with independent cast accounts and a protected store
administrator. Stage readiness is 3 of 3 because source verification, account
and permission tests, additive migration, secret injection, versioned release,
rollback evidence, public HTTPS smoke and production database checks passed.

`Version 2b3a737 / Overall Maturity L3 within production cast attendance access / Evolution Capability E4 / Confidence high`

## Overall conclusion

The release is suitable for the declared shop Alpha. Cast members have a
profile-bound self-service path, while the administrator retains authority to
manage all active schedules and the full review and publication lifecycle.
Public browsing and the staff portal work without OpenAI or ChatGPT accounts.

The overall maturity remains L3. The implementation, security boundary,
migration, deployment and rollback chain are integrated. Real staff account
delivery, one complete staff-to-admin production task and operating offboarding
practice still need observational evidence.

## Decision impact

Release the accepted candidate to the current production domain. Keep account
creation intentional and administrator-controlled. Do not expand into booking,
payments, payroll or sensitive personnel data under this release boundary.

## Topology and critical path

Cast member → `/staff` → site-owned credential → signed session cookie → active
account and session-version check → bound `artistSlug` → own draft and submit →
administrator review → published anonymous projection.

Administrator → Caddy Basic Auth → trusted proxy marker → administrator-wide
attendance command → version check → SQLite transaction and append-only event →
status-preserving public update when already published.

Release candidate → verified commit → read-only standalone release → `current`
pointer → Keychain-backed startup script → LaunchAgent → migration 3 → local
health → unchanged Caddy route → public HTTPS smoke.

The production path is closed for the declared Alpha. The weakest interface is
the human process that delivers, rotates and revokes a cast access code.

1. Cast access adds a new credential and session surface. Scrypt hashes,
   HttpOnly cookies, rate limiting, session versions and administrator-controlled
   lifecycle contain the current Alpha risk.
2. Administrator edits reuse the existing `save_draft` stored action while the
   audit detail identifies `ADMIN UPDATE`. A dedicated database action can wait
   until reporting semantics require it.
3. The first symlink replacement attempt triggered a safe rollback because
   macOS `mv` followed the directory link. The successful run uses `mv -h` and
   records this behavior in the release receipt.
4. The generic Caddy renderer would remove the existing Basic Auth block. This
   release used App Deployer preflight plus a manual launch-only switch and
   verified that the Caddy checksum did not change.

## Evolution capability

E4 remains supported within the evaluated scope. Human Owner feedback changed
the permission model, the correction propagated through domain rules, storage,
UI and tests, and the accepted candidate passed an independent release review.
The production switch encountered a real filesystem behavior difference,
restored the previous release, corrected the operation, repeated the switch and
closed with the full 37-test regression suite plus local, public, database and
rollback evidence.
