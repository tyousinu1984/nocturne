# Nocturne Administrator Attendance Control Assessment

## Evaluation context

This assessment records the correction from a review-only store operator to an
operator who can create and edit attendance for every cast profile. Cast
members remain limited to creating, saving and submitting drafts for the
profile bound to their account. Rejected and cancelled records remain immutable
history.

The target environment is still the isolated development candidate. Production
deployment, customer workflows, payroll and published-entry change requests
originated by cast members remain outside scope.

Target stage: accepted production candidate. Stage readiness remains 2 of 3
because implementation and verification pass, while production migration and
smoke evidence remain pending.

`Version codex/feature/cast-schedule-access / Overall Maturity L3 within administrator-wide attendance control in isolated development / Evolution Capability E4 / Confidence high`

## Overall conclusion

The corrected model now matches the stated store workflow. Administrators can
create a schedule for any profile, edit drafts, pending submissions, approved
records and published records, and continue the normal review and publication
commands. An administrator edit preserves the current lifecycle status,
increments the aggregate version and appends an audit event. A published edit
therefore updates the anonymous projection immediately without losing history.

The overall development maturity remains L3. The change corrects an authority
boundary and does not add a new persistence model or migration.

## Decision impact

Continue controlled validation with this corrected permission matrix. The
production domain and database remain unchanged until Human Owner acceptance
and the existing release gates pass.

## Topology and critical path

Administrator → protected admin route → select any profile or active attendance
→ create or edit command → server-side administrator permission → version check
→ SQLite aggregate and append-only event → current status preserved → public
projection updated when status is already published.

Cast member → staff session → bound `artistSlug` → own draft only → submit →
administrator review.

The corrected development path is closed. The weakest interface remains the
candidate-to-production release chain.

## Change quality, risk and debt

变更类型：缺陷修复、结构优化、闭环补全；依据：用户指出管理员缺少跨人物日程维护权，修改同步传播到领域模型、权限函数、状态转换、后台界面、自动化测试和浏览器验收。

1. Administrator edits to active records reuse `save_draft` as the stored action
   while the audit detail and UI identify `ADMIN UPDATE`. This avoids an
   unnecessary SQLite table reconstruction in the current Alpha.
2. Published corrections update public time immediately. The action remains
   versioned, idempotent and auditable.
3. Rejected and cancelled entries remain terminal. Administrators create a new
   active entry instead of rewriting historical outcomes.
4. Cast permissions did not expand and still require exact profile binding.

## Evolution capability

E4 remains supported. The before-change baseline limited the operator to review
actions. Human Owner feedback identified that business-model error, the
discrepancy was traced to the permission matrix, and the correction propagated
through domain rules and UI behavior. The full regression suite of 37 automated
tests passed, and browser QA proved both a live published correction and
cross-profile administrator creation. The final page produced no console
warnings or errors.
